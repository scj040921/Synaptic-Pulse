# 分阶段开发与验收

项目申请书是产品目标与研究设想，不能当成已实现功能。以可验收的最小版本逐步推进。

| 阶段 | 工作 | 验收标准 | 状态 |
| --- | --- | --- | --- |
| 1 基础闭环 | 账号、资料、兴趣匹配、动态、私聊、屏蔽、AI 练习接口；改造现有 UI | 两个体验账号可互相匹配、发动态与聊天；后端集成测试通过 | 代码已完成；跨端编译待验收 |
| 2 校园试点 | 校园身份认证、找回与注销、举报与审核、访问限流、数据库迁移和备份 | 非同校账号无法进入；举报可处置；迁移可回滚 | 待做 |
| 3 推荐研究 | 获得明确授权后采集兴趣与互动数据；建立可复现基线、离线指标与 A/B 实验，再评估图模型 | 能比较基线与新模型的效果、公平性、延迟与资源成本 | 待做 |
| 4 限时互动 | 匿名漫游、双人协作任务、脉冲积分与成就 | 匿名到实名必须双方同意；反骚扰与退出机制可用 | 待做 |
| 5 位置与 AR | 先做可选位置权限、粗粒度信号与 250 米范围校验，再评估地图/AR | 不暴露精确坐标；关闭权限后功能不可读取位置；实机性能达标 | 待做 |
| 6 多端发布 | Web、Android 真机、微信小程序逐端测试、修复与部署 | 各端同一账号完成注册、匹配、发帖与聊天；服务使用 HTTPS | 待做 |

## 下一阶段优先事项

1. 在完整 HBuilderX 环境编译 Web 和 Android，修正平台 CSS/API 差异，并做手机与 Windows 浏览器视觉验收。
2. 用学校认可的认证方式替换体验账号。不要把普通账号的 `campus` 字段当作已核验身份。
3. 将 H2 切换到 PostgreSQL，并使用版本化迁移；补充会话管理、限流、审核与举报。
4. 再开展模型试验，记录训练数据来源与用户同意范围。模型效果没有离线/线上证据时保留基线实现。
